



**Java Blueprints** — это интерактивная веб-среда(mvp) на базе **.NET 8** и **ASP.NET Core Blazor Interactive Server**, предназначенная для визуализации, статического анализа, поиска узких мест ($O(n^2)$), автоматического рефакторинга и проверки поведения (Quality Gate) Java-программ.

---

## Основные возможности : 

1. **Двусторонняя синхронизация (Код ⇄ Граф):**
   - Прямой проход: парсинг исходного Java-кода в визуальную блок-схему (`BlueprintGraph`).
   - Обратный проход: мгновенная генерация валидного, со 100% сбалансированными скобками (`{}`) Java-кода при редактировании карточек на холсте или добавлении блоков из палитры
2. **Устойчивость к сложному синтаксису (Stream API, лямбды, `::`):**
   - Усовершенствованный препроцессор склеивает многострочные чейнинги Stream API (`.stream().filter().collect()`) в единые логические блоки, не теряя код при генерации
   - Поддержка произвольных имен классов и директив `package` (автоматическая адаптация для компилятора).
3. **Статический анализатор и Big O детекция:**
   - Вычисление асимптотической сложности ($O(1)$, $O(n)$, $O(n^2)$) через отслеживание стека вложенных циклов и Stream-конвейеров.
   - Детекция антипаттернов (длинные методы, скрытый $O(n^2)$ через `List.contains`, отсутствие `StandardCharsets.UTF_8`)
4. **Автоматический рефакторинг в 1 клик:**
   - Замена квадратичного обхода $O(n^2)$ на линейную индексацию через `LinkedHashMap` за $O(n)$ с сохранением порядка элементов (идентичный `stdout`)
   - Декомпозиция монолита на 4 SRP-класса (`Parser.java`, `Analyzer.java`, `Optimizer.java`, `Main.java`)
5. **Quality Gate (Верификация поведения):**
   - Изолированная компиляция через реальный `javac` и запуск на 5 тестовых наборах (`stdin`, нагрузочный тест на 1523 элемента).
   - Защита от зависаний: жесткий таймаут (5 секунд) с принудительным завершением процесса через `Kill(true)`

---

## 🛠 Технологический стек
- **Backend / UI Framework:** .NET 8, ASP.NET Core Blazor Server (`InteractiveServer` render mode)
- **Парсинг и Анализ:** Кастомный AST-пайплайн на регулярных выражениях (`System.Text.RegularExpressions`), препроцессор с сохранением исходных строк
- **Интеграция с JDK:** `System.Diagnostics.Process`, асинхронное чтение потоков ввода-вывода (`BeginOutputReadLine`)

## ⚠️ Ограничения MVP и известные краевые случаи

Поскольку **Java Blueprints** разработан как mvp в рамках хакатона и использует легковесный пайплайн на регулярных выражениях (`Regex`) вместо AST-библиотек , проект имеет ряд естественных архитектурных ограничений:

1. **Сложный синтаксис и сторонние конструкции:**
   - **Лямбды и Stream API:** Поддерживаются базово (парсер не падает), но детальная декомпозиция цепочек `.map().filter().reduce()` внутри визуального графа в текущей версии не раскрывается в отдельные подблоки
   - **Многострочные лямбды и анонимные классы:** Сложные конструкции вроде `new Runnable() { @Override public void run() { ... } }` могут нарушить баланс фигурных скобок `{}` при обратной генерации кода

2. **Форматирование кода и комментарии:**
   - Парсер рассчитывает на стандартный стиль кодирования (где открывающая скобка `{` находится на той же строке или строго под ней). Экзотическое форматирование с переносом скобок может привести к некорректному расчету глубины `Depth`
   - Однострочные комментарии внутри блоков кода (например, посередине метода) могут сместить сопоставление номеров строк `SourceLine`.

3. **Ограничения Quality Gate (Верификации):**
   - **Формат выводных данных (`stdout`):** Тесты Quality Gate завязаны на эталонный формат вывода демо-задачи (`COUNT=... | TOTAL=...`). Если пользователь загружает в редактор абсолютно произвольный сторонний Java-код (не связанный с нашей доменной моделью заказов), тесты выдадут статус «Расхождение», так как их ожидания не совпадут с логикой печати сторонней программы.
   - **Зависимость от локального окружения:** Для реальной компиляции и замеров времени выполнения на компьютере должен быть установлен и прописан в системную переменную `PATH` актуальный JDK (`javac` и `java`). При его отсутствии система автоматически переключается на безопасную симуляцию

4. **Интерфейс и редактор:**
   - Редактирование текста внутри карточки блока на холсте (`input`) предназначено для точечных правок выражений. Пытаться вставить туда многострочный код с фигурными скобками не рекомендуется — для глобальных изменений следует использовать вкладку текстового редактора Java снизу.
